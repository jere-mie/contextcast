# Narration

Aim for a 5–10 minute standard PR explanation only when the evidence warrants it; never pad. Most beats should be 12–30 words, approximately 5–12 seconds. The compiler reports estimated duration and soft length notes.

Narration should explain reasoning and consequences rather than read the visual verbatim. Define unfamiliar terms before showing implementation details. Use signposts such as “First, the existing path” and “Here is the risk.” Speak function names and symbols naturally. Keep raw URLs, Markdown, and complete code blocks out of `speech`.

The exact speech is the transcript. `caption` is optional display copy; it never replaces the transcript. Say what the evidence establishes and distinguish an observed behavior from a hypothesis. End with a concrete action or decision. The viewer estimates navigation from word counts; actual speech end events advance the presentation. Write short beats so approximate replay is useful.
